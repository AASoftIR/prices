# BahaBar GitHub TGJU crawler — 2026-11-23 reliability pass

This is the source intended for the user's **AASoftIR/prices** GitHub crawler. It is not a deployment: copy the updated files to that repository and run its existing GitHub Actions workflow. **The Android app remains separate and preserves GitHub as the primary data source.**

## Fixed in extractor v3

1. **Hidden historical prices**: ignore display:none, visibility:hidden, aria-hidden and hidden ancestors/cells before selecting any displayed table price. The old hidden/template rows should not replace the visible dollar quote.
2. **Partial feed safety**: no longer reject an otherwise useful 30+ market snapshot merely because one optional currency disappears during site changes. Still require USD, gold18k, Emami coin, BTC, USDT, at least 12 markets, and domain relationship checks.
3. **Wrong-unit checks**: reject USDT/USD, coin/gold, BTC/USD, ounce/USD and 24K/18K ratios inconsistent with the expected Toman representation.
4. **Honest source time**: `generated_at` means the GitHub fetch completed recently; `source.market_time_verified=false` says it does NOT prove that TGJU traded recently. The per-market Persian `observed_label` is kept.
5. **Provenance and visibility**: `extractor_version=3`, `missing_markets` lists optional absent symbols, `validate_json.py` fails before the publish step on unsafe content, and new regression tests exercise hidden cells and suspicious ratios.
6. **Bounded fetch**: the normal HTTP path streams in 64 KiB chunks with a 4 MB cap and checks HTTPS after redirects; the Chrome-impersonation fallback rejects over-cap bodies before parsing.

The v2 parser already avoided stale `data-price` attributes. That protection remains.

## Verification

- Python files compile under the available Python interpreter.
- A dependency-free check of the pure quote validator passed for a 13-market partial payload, provenance, optional coverage reporting, and rejected a 10× wrong USDT value.
- New and existing pytest test cases are provided for the GitHub workflow.
- `pytest` and `beautifulsoup4` are unavailable locally here, so the test suite was **not executed** in this environment.
- No live TGJU prices were fetched or compared against a browser in this environment; the included Nov 12 captured fixture remains the regression baseline.

## Deployment

1. Back up or branch the current `AASoftIR/prices` crawler code; keep the existing `market-data` feed online.
2. Copy `scripts/`, `tests/`, `requirements.txt`, and `.github/workflows/update-tgju-prices.yml` from this package into the correct GitHub repository.
3. Run **Actions → Update TGJU market data → Run workflow** and check parser tests, `validate_json.py`, and the published `data/latest.json`.
4. Verify displayed USD, gold18k, Emami, BTC and USDT against the TGJU browser page in the same instant. Distinguish IRR from Toman; market closure is not freshness.
5. Verify the Android app's Source Diagnostics and widgets show the live feed, with the intended fallback order unchanged.

GitHub Actions cron is best effort; it does not guarantee a run every five minutes. Do not treat the `generated_at` field as proof of a fresh market trade.
